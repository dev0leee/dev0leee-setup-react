# 컨벤션

이 프로젝트의 코드 규칙 모음.

**각 문서는 "지금 커뮤니티는" 절로 시작한다.** 2026년 7월 기준으로 React 커뮤니티가 실제로 무엇을 쓰고 무엇을 두고 싸우는지를 먼저 적고, 그 다음에 **우리가 어느 쪽을 골랐는지와 그 이유**를 적었다. 근거는 Reddit·X·HN·GitHub 원문과 1차 블로그 글이며 링크가 달려 있다.

그래서 이 문서들에는 세 종류의 문장이 섞여 있다. 구분해서 읽는다.

| 문장 유형                     | 표기                                                | 다룰 방법                                                        |
| ----------------------------- | --------------------------------------------------- | ---------------------------------------------------------------- |
| 커뮤니티가 합의한 것          | "지금 커뮤니티는" 절, 인용 + 링크                   | 따른다                                                           |
| 커뮤니티가 **싸우는 중**인 것 | 양쪽 논거를 다 적고 "이 프로젝트의 결정"으로 마무리 | 결정을 따르되, 뒤집고 싶으면 그 절의 반대 논거를 근거로 제안한다 |
| 이 레포의 기존 코드 사실      | 파일 경로가 명시됨 (`src/api/client.ts` 등)         | 코드가 진실이다. 어긋나면 문서를 고친다                          |

**"이 프로젝트의 결정"에는 재검토 조건을 같이 적어뒀다.** 예: barrel 파일은 feature 10개 초과 시, TanStack Form은 중첩 동적 폼이 생길 때. 조건이 충족되면 개인 판단이 아니라 팀 논의로 다시 연다.

## 규칙의 등급

각 문서는 세 등급으로 표기한다.

- **MUST** — 어기면 리뷰에서 반려. 대부분 린터/타입체커가 잡는다.
- **SHOULD** — 기본값. 어길 거면 PR 설명에 이유를 쓴다.
- **MAY** — 취향. 팀이 합의하면 바꾼다.

## 자동화되는 규칙

사람이 지킬 필요 없는 것들. 도구가 강제한다.

| 규칙                                           | 강제하는 도구                                         |
| ---------------------------------------------- | ----------------------------------------------------- |
| 세미콜론 없음, 홑따옴표, 100칸, trailing comma | Prettier (`.prettierrc.json`)                         |
| Tailwind 클래스 정렬                           | `prettier-plugin-tailwindcss`                         |
| `any` 금지, `import type` 강제, `eqeqeq`       | oxlint (`.oxlintrc.json`)                             |
| 훅 규칙, exhaustive-deps                       | oxlint `react/*`                                      |
| 미사용 변수/파라미터, 인덱스 접근 안전성       | tsconfig `noUnusedLocals`, `noUncheckedIndexedAccess` |
| 커밋 전 lint + format                          | husky + lint-staged                                   |

그래서 이 문서들은 **도구가 못 잡는 것**에 집중한다.
